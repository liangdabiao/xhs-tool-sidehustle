# 阶段 1：候选赛道的小红书长尾验证

> 输入：阶段 0 的候选工具词清单。本阶段给每个候选词拿「需求规模 + 用户口语」两组数据。

## 1.1 需求规模：5118 小红书挖词

`scripts/mine_5118_xhs.py`（bsk，需 5118 登录）逐词查询，产出长尾词总量。

实测路径（2026-11-24）：
- 落地页 `https://www.5118.com/ci/xhs`；结果页 `https://www.5118.com/xhs/words/<token>`，标题「<实际命中词> 小红书长尾关键词挖掘」
- **token 跨平台通用**（seo/douyin/xhs 同词同 token）
- 总量解析：vom「相关小红书长尾词共找到」前 ~25 行的 emphasis 数字节点（小红书版一个数字）
- 5118 会把查询词扩展成关联短语（如「简历制作」→「简历制作-免费模板…|在线制作个人简历」），脚本按标题后缀匹配并记录实际命中词

## 1.2 用户口语：搜索联想词

`scripts/xhs_suggest.py`（bsk，需小红书登录）对同一批词采集联想短语（每词 20-35 条真实口语）。这些短语直接回答三个问题：
- 用户卡在哪（怎么X / X不了）
- 用户要什么形态（免费 / 网页版 / 小程序 / 快捷指令）
- 用户纠结什么（哪个好用 / 准确率高 / 不伤原图）

## 1.3 结果表字段

`01_mining/xhs_words.csv`：word, total(长尾词总量), matched_title(实际命中词), ts
`01_mining/xhs_suggest.csv`：word, suggest(|分隔), ts

## 1.4 规模纪律

- 目检级（几十词）：直接跑；数百词：联想+标签交叉拓展后分批跑；数万词以上：向用户索要 5118 API（付费），在登录态内按平台正常节奏使用
